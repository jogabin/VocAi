확인: 정리한 사람 (2026-10-24, 고침 2026-10-25. 범위 변경에 맞춰 추천대로 고침, 2026-10-25) · 팀 (2026-10-25 알림승인 합침까지 확인. 범위 변경으로 고친 것까지 다시 확인함 (2026-10-25). 팀 검토 전이라, 노션 사본의 팀 의견이 오면 옮기고 확인 대기로 되돌려 다시 확인받음)   · 범위 변경에 맞춰 고침 (팀 질문 답, 2026-10-26) · 다시 확인 팀, 2026-10-26 (범위 변경으로 고친 것까지 확정) · 범위 변경(역할 넷과 탭 2·3 나눔)에 맞춰 고침 (팀 질문 답, 2026-10-27) · 다시 확인 팀, 2026-10-27 (범위 변경으로 고친 것까지 확정) · 10/27 v2(VocAi) 비교 보강 반영, 팀이 「알아서 판단」으로 맡김 (사람이 읽고 확인한 것은 아님, 확인 대기)
팀 검토 사본: 없음 (공유용 노션 사본: 요건정의-요건정리, 검토 전이라 원본은 이 파일)  
진행 방식: 탭마다 초안 (공통 요건 → 탭 1~7 순서, 2026-10-23)

> 사용자, 탭 목록, 공통 요건입니다. 탭의 요건은 `tabs/`의 탭 파일에 있습니다.  
> 아키텍처와 디자인은 작성 중인 파일로도 초안을 쓰지만, 확정은 이 파일들이 모두 확정된 뒤에 합니다. 여기서 정한 요건은 다시 정하지 않습니다.  
> 고쳐야 하면 요건정리로 되돌려 보냅니다.

## 사용자

| 사용자 | 하는 일 |
|---|---|
| 상담사 | 끝난 상담의 이력을 등록합니다(탭 1). 같은 장애로 다시 문의가 오면 탭 1에서 그 장애의 처리 상태와 회신을 보고, 고객에게 안내한 기록을 남깁니다. |
| 상담사관리자 | 자료의 센터관리자입니다. AI가 P2·P3로 본 장애를 확인하고 등급과 알림 내용을 고쳐 승인하거나 반려하고, 장애의 등급을 고칩니다(탭 2). 승인 없이 바로 알린 P1까지 모든 장애를 봅니다. |
| IT 담당자 | IT팀 안에서 업무마다 담당이 나뉩니다(자료의 업무부서 담당자 포함). 맡은 장애의 P1 알림과 승인된 P2·P3 알림을 받고, 처리 상태와 결과(회신, 확정한 원인)를 등록합니다. AI가 오탐으로 판별한 장애를 바로잡습니다(탭 3). |
| 관리자 | 모든 화면을 보는 시스템 관리자입니다. 판별 기준, 담당자 정보와 계정, 역할마다 쓸 수 있는 화면, 시험 상담을 관리하고 성과를 봅니다(탭 4~7). 처음에는 탭 1~3도 켜져 있습니다(5-06). |
