# ADR-015 같은 원인 제보는 AI 판단으로 묶고, 단독 제보의 P1은 조건이 확인될 때만 준다

- 상태: 채택
- 날짜: 2026-11-02

## 요약

1. **같은 원인 묶기**: 중복제보 통합 단계에서 증상 글자 유사도로 묶이지 않아도, 60분 안의 같은 오류유형·같은 채널 미해결 장애가 있으면 '같은 원인'인지 한 번 더 판단합니다. LLM을 쓰면 AI가 판단하고, 쓰지 않거나 실패하면 규칙(둘 다 같은 계기 '업데이트'를 말하고 앱 버전이 다르지 않음)으로 판단합니다.
2. **단독 제보의 P1 상한**: 대규모 장애 신호 전 제보가 감지 후보·AI 판단만으로 P1이 되면 P2(관찰)로 둡니다. P1은 판별기준의 키워드 조정 규칙(기한 임박·금전 피해 등)이 걸리거나, 대규모 장애 신호이거나, 이미 P1인 장애에 통합될 때만 줍니다.

## 배경

- 대규모 장애 신호 시연에서 같은 원인(오늘 앱 업데이트 후 로그인 실패)의 제보가 하나로 묶이지 않았습니다. 고객마다 보이는 증상(반응 없음, 로딩 계속, 로그인 화면 복귀, 앱 종료)이 달라 증상 글자 유사도가 0.07~0.16으로, 통합 최소 기준 0.20에 못 미쳤습니다(`rules.similarity`, 로컬 계산값).
- 표현이 같은 인증 오류 제보도 AI가 정리한 증상 문장의 표현 차이로 0.14~0.18에 그쳐 묶이지 않았습니다.
- 첫 제보가 'P1 로그인 유형'과 비슷하면 고객 1명이어도 AI가 P1로 판단해 바로 알림을 보냈습니다. 그 뒤 대규모 신호가 붙어도 이미 P1로 알린 장애라 다시 알리지 않아, '대규모 신호로 P1 상향' 흐름이 나오지 않았습니다.
- 판별기준의 P1 정의는 기한 임박·중대한 피해·대체수단 없음·다수 고객 같은 영향 조건입니다(`10_impact_improvement.sql`).

## 검토한 안

### 같은 원인 묶기

| 안 | 내용 | 단점 |
|---|---|---|
| 안 1 | 유사도 기준값을 낮춤 | 다른 증상도 묶일 위험이 커짐. 0.07 수준까지 낮추면 기준이 의미 없음 |
| 안 2 | 장애에 묶인 제보들의 고객 원문과도 비교 | 표현이 다른 제보(0.14)는 여전히 못 묶음 |
| 안 3 | 임베딩 의미 비교 | 임베딩 모델·키·벡터 저장 준비가 필요하고, 지금 설정은 문자열 유사도(`RAG_SEARCH=text`) |
| 안 4 (고른 안) | 글자 유사도로 못 묶일 때만 AI가 같은 원인인지 판단, AI가 없으면 규칙 | 후보가 있는 경우에만 LLM 호출 1회가 늘어남 |

### P1 판정

| 안 | 내용 | 단점 |
|---|---|---|
| 안 1 | 그대로 둠 (AI가 단독 제보도 P1 가능) | 시연·운영 모두 첫 제보에서 바로 P1 알림이 나가 대규모 신호 흐름이 안 보임 |
| 안 2 | 'P1 로그인 유형' 상담 정의를 고침 | 유형 상담마다 손봐야 하고, AI 판단은 여전히 P1을 낼 수 있음 |
| 안 3 (고른 안) | 판별 마지막에 상한: 조건 규칙·대규모 신호가 없으면 P2 | 기한·피해 표현이 키워드 규칙에 없으면 단독 제보는 P1이 안 됨 → 판별기준 관리에서 키워드를 더해 맞춤 |

## 결정

- 같은 원인 묶기는 안 4, P1 판정은 안 3으로 정했습니다.
- AI에게는 '같은 기능이 같은 계기(같은 업데이트·시간대) 뒤로 실패하는지'를 묻고, 기능이 다르거나 계기가 맞지 않거나 확실하지 않으면 묶지 않도록 했습니다. 묶은 근거는 통합 단계 메시지와 결과(`same_cause`)에 남깁니다.
- P1 조건 확인은 적용 기록이 아니라 키워드 규칙이 실제로 걸리는지로 봅니다. 감지 단계에서 이미 P1 후보면 규칙을 적용해도 등급이 그대로라 적용 기록에 남지 않기 때문입니다.
- 상한을 적용하면 `[P1 조건 미확인]` 근거를 남깁니다.

## 결과

- 코드: `backend/app/agents/dedup.py`(`_same_cause`), `backend/app/agents/severity.py`(`_top_condition`, `_cap_unconfirmed_top`)
- 시연 데이터: `backend/sql/15_demo_large_signal.sql` 의 PR_P1_LG_1~4 (증상이 다른 같은 원인 제보 4건)
- 로컬에서 실제 에이전트로 2회 확인: 1·2번째는 같은 장애로 묶이고 P2 관찰, 3번째에서 독립 고객 3명 → 대규모 장애 신호 → P1 알림, 4번째는 같은 장애에 누적되고 중복 알림은 생략. PR_P1(이체 기한 임박)은 기한 임박 규칙으로 P1 유지.
- 60분 안에 같은 유형·채널의 다른 미해결 장애가 열려 있으면 그 장애에 묶일 수 있습니다. 시연 전에는 데이터 초기화로 정리합니다.
