# ADR-001 폴더 구조

- 상태: 채택
- 날짜: 2026-10-20
- 바뀐 점: `docs/design/`은 `docs/spec/`으로, `docs/tasks/`는 `docs/plan/`으로 이름을 바꿨습니다(2026-10-21, [ADR-002](ADR-002-dev-flow-and-agents.md)).
- 이 저장소로 옮긴 때(2026-10-30): 이 저장소에는 앱 코드(`backend/`, `frontend/`)가 이미 맨 위에 있어서, 아래에서 정한 폴더(`.claude/`, `harness/`, `docs/`)를 그 옆에 두었습니다([ADR-010](ADR-010-submission-implementation.md)).
- 참고: 이 문서의 `design/`은 설계를 뜻합니다. 지금의 `docs/design/`은 화면 디자인 폴더입니다(2026-10-22, [ADR-002](ADR-002-dev-flow-and-agents.md)).

## 배경

이 저장소에는 다섯 종류의 파일이 들어갑니다.

- adr
- Claude 실행 시 지킬 규칙 (harness)
- 우리가 만드는 에이전트
- 개발 단계마다 만드는 문서(산출물)
- 앱 코드 (나중에 추가)

처음에 구조를 잘못 잡으면, 파일이 늘어날수록 찾기도 고치기도 어려워집니다.  
그래서 개발을 시작하기 전에 프로젝트 구조부터 깔끔하게 정했습니다.

## 지켜야 할 조건

1. 응집도와 결합도를 고려한 폴더 구조
2. 쉽게 이해할 수 있는 프로젝트 구조, 문서 구조

## 검토한 안

### 안 1. 에이전트 폴더를 따로 두고, 스크립트로 연결하기

```
VocAi/
├── agents/        ← 에이전트를 여기에 둠
├── rules/
├── docs/
└── setup.ps1      ← 팀원마다 한 번씩 실행해야 에이전트가 동작함
```

| 구분 | 내용 |
|---|---|
| 장점 | 폴더 이름이 눈에 잘 띕니다. |
| 단점 | 팀원마다 `setup.ps1`을 실행해야 합니다.<br>실행을 잊으면 에이전트가 보이지 않습니다. |
| 결과 | 에이전트 폴더와 연결 스크립트가 서로 묶여 있습니다.<br>한쪽을 바꾸면 다른 쪽도 고쳐야 해서 결합도가 높습니다. |

### 안 2. Claude Code 기본 폴더 `.claude/`에 두기

```
VocAi/
├── CLAUDE.md
├── .claude/
│   ├── skills/    ← Claude Code가 자동으로 찾음
│   ├── agents/    ← Claude Code가 자동으로 찾음
│   └── hooks/
├── harness/
└── docs/
```

| 구분 | 내용 |
|---|---|
| 장점 | 내려받기만 하면 바로 동작합니다.<br>따로 설정할 것이 없습니다. |
| 단점 | 맥이나 리눅스에서는 이름이 점(.)으로 시작하는 폴더가 숨김 폴더가 됩니다.<br>그래서 폴더가 있는지 모르고 지나칠 수 있습니다. |
| 결과 | Claude Code용 파일은 `.claude/`에, 규칙은 `harness/`에, 문서는 `docs/`에 모입니다.<br>같은 종류끼리 모여 있고(응집도 높음), 폴더끼리 서로 기대지 않습니다(결합도 낮음).<br>숨김 폴더 문제는 README에 폴더 설명을 적어서 보완합니다. |

### 안 3. 모든 폴더를 맨 위에 나란히 두기

```
VocAi/
├── skills/
├── agents/
├── rules/
├── requirements/
├── design/
├── tasks/
├── verification/
├── deploy/
├── adr/
└── (앱 코드 폴더들)
```

| 구분 | 내용 |
|---|---|
| 장점 | 구조가 단순합니다. |
| 단점 | 폴더가 10개가 넘습니다.<br>이 위치에 둔 `skills/`, `agents/`는 Claude Code가 자동으로 찾지 못합니다. |
| 결과 | 규칙, 에이전트, 문서 폴더가 한 층에 섞여 있습니다.<br>같은 종류끼리 모이지 않아 응집도가 낮고, 구조를 한눈에 알아보기 어렵습니다. |

### 한눈에 비교

## 결정

안 2로 정했습니다.  
두 조건을 가장 잘 지키는 안이고, 내려받기만 하면 바로 동작하는 안도 안 2뿐입니다.

나머지 폴더는 이렇게 정했습니다.

- `harness/`: 규칙을 `CLAUDE.md`에 직접 쓰지 않고 이 폴더에 둡니다.  
  규칙이 많아져도 `CLAUDE.md`는 짧게 유지됩니다.
- `docs/`: 사람이 읽는 문서는 모두 여기에 둡니다.  
  안쪽 폴더는 개발 순서대로 나눴습니다.

```
docs/
├── requirements/   1. 요건
├── design/         2. 설계
├── tasks/          3. 작업
├── verification/   4. 검증
├── deploy/         5. 배포
├── architecture/   구조 설명
├── guide/          사용 안내
└── adr/            결정 기록 (이 문서)
```

## 주의할 점

- Claude Code는 꼭 이 저장소 폴더에서 열어야 합니다.  
  다른 폴더에서 열면 에이전트가 보이지 않습니다.
- `.claude/agents/` 안의 `.md` 파일은 모두 에이전트로 인식됩니다.  
  그래서 이 폴더에는 설명 파일을 두지 않습니다.  
  설명은 루트 README에 있습니다.
- 앱 코드 폴더는 이 문서를 쓸 때 정하지 않았습니다.  
  지금은 `backend/`(FastAPI)와 `frontend/`(Vue)가 저장소 맨 위에 있습니다([ADR-007](ADR-007-tech-stack.md), [ADR-010](ADR-010-submission-implementation.md)).
