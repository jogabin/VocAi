# ADR-013 시연 데이터는 재배포 없이 화면에서 초기화한다

- 상태: 채택
- 날짜: 2026-10-30

## 요약

시스템관리자가 시스템관리 > 데이터 초기화 화면(SCR-12)에서 시연 데이터를 처음 시연 상태로 되돌립니다.  
되돌리는 것은 상담·장애·알림·에이전트 실행·개선의견이고, 계정·인사정보·판별기준·고객정보는 그대로 둡니다.  
배포 때 쓰던 `DB_RESET_TOKEN`(계정까지 전체 초기화)은 그대로 남겨 둡니다.

## 배경

- 시연을 여러 번 하면 상담이력과 장애가 쌓여서, 다음 시연 전에 처음 상태로 되돌려야 합니다.
- 지금까지는 `DB_RESET_TOKEN` 값을 바꿔 재배포하거나 서버에서 `scripts/init_db.py --reset` 을 실행해야 했습니다. 초기화할 때마다 재배포하기는 어렵고, axhub 안에서 스크립트를 실행하는 방법은 확인하지 못했습니다([배포 문서](../deploy/deploy.md) 5절).
- 시연 사이에 판별기준을 고치거나 계정을 추가해 두는 경우가 있어, 그것까지 지우면 다시 설정해야 합니다.

## 검토한 안

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| 안 1 | 지금처럼 `DB_RESET_TOKEN` 재배포 | 새 코드 없음 | 초기화마다 재배포. 계정·판별기준도 지워짐 |
| 안 2 | 화면에서 전체 초기화(`--reset` 과 같음) | 기존 함수 재사용 | 계정·판별기준이 지워지고, 실행한 관리자도 로그아웃됨 |
| 안 3 (고른 안) | 화면에서 시연 데이터만 초기화 | 재배포 없음. 계정·판별기준 유지 | 시드 파일 중 시연 데이터 쪽만 골라 다시 실행해야 함 |

사람이 안 3을 골랐습니다(2026-10-30). 화면 위치는 시스템관리 메뉴의 새 화면으로 정했습니다.

## 결정

- 시연 데이터 테이블 11개(`stt_call`, `stt_utterance`, `consult_history`, `incident_alert`, `incident_report`, `incident_action`, `incident_embedding`, `messenger_log`, `agent_run`, `agent_step`, `improvement_opinion`)를 비우고 번호를 1부터 다시 시작합니다.
  - 다른 테이블이 이 11개를 참조하지 않는 것을 로컬 DB에서 확인했습니다. 그래서 CASCADE 없이 비웁니다. 새로 참조하는 테이블이 생기면 초기화가 실패하므로, 모르게 지워지지 않습니다.
- 시연 데이터를 넣는 시드 파일만 다시 실행합니다: `02_seed`, `06_consult_agent`, `07_incident_process`, `08_customer_consult_data`, `11_demo_scripts`, 그리고 과거 상담 데이터(`history_seed`).
  - 계정·판별기준을 바꾸는 `04`, `05`, `09`, `10`, `13` 은 실행하지 않습니다. 이 파일들은 판별기준 값을 UPDATE 하므로 다시 실행하면 화면에서 고친 기준이 되돌아갑니다.
  - 다시 실행하는 파일은 없는 행만 넣습니다. 그래서 지운 기본 직원·고객은 시연 데이터와 맞추려고 다시 생기고, 고친 내용은 바뀌지 않습니다.
- 실수로 지우지 않도록 시스템관리자만 쓰고, '초기화'를 직접 입력해야 실행합니다. 마지막 실행 시각과 실행자를 `app_meta`(`demo_reset`)에 남겨 화면에 보여 줍니다.
- 과거 장애 검색(RAG) 임베딩은 비운 뒤 다시 만들지 않고, 첫 검색 때 다시 만듭니다(기존 동작).

## 결과

- 코드: `backend/app/db_init.py` 의 `reset_demo_data`, `backend/app/routers/admin_api.py` 의 `GET·POST /api/admin/demo-reset`, `frontend/src/views/DataResetView.vue`
- 초기화하는 동안 다른 화면의 조회를 15초까지 기다리고, 그래도 막히면 실패를 알립니다. 시연 중에 누르면 진행 중인 데이터가 사라지므로 화면에 경고를 둡니다.
