# ADR-014 기존 DB에 꼭 반영할 SQL은 서버 시작 때 한 번만 적용한다

- 상태: 채택
- 날짜: 2026-10-30

## 요약

`backend/app/db_init.py` 의 `UPDATE_SQL_FILES` 에 넣은 SQL 파일은 서버가 시작할 때(재배포 포함) 아직 적용하지 않은 것만 한 번 실행하고, `app_meta` 에 `sql:<파일명>` 으로 기록합니다. 기록이 있으면 다시 실행하지 않습니다.  
첫 대상은 IT담당자 초기 계정을 `user02 / user02` 에서 `user / user` 로 바꾸는 `14_rename_it_account.sql` 입니다.

## 배경

- 시드 SQL은 빈 DB일 때만 자동으로 실행됩니다(`init_if_empty`). 이미 데이터가 있는 배포 DB에는 새 SQL이 들어가지 않습니다([배포 문서](../deploy/deploy.md) 5절).
- 계정 이름을 바꾸라는 요청이 왔는데, 시드만 고치면 배포된 DB의 `user02` 는 그대로 남습니다.
- `DB_RESET_TOKEN` 으로 전체 초기화하면 반영되지만, 다른 데이터까지 모두 지워집니다.

## 검토한 안

| 안 | 내용 | 단점 |
|---|---|---|
| 안 1 | 시드(05)만 고침 | 배포된 DB에는 반영되지 않음 |
| 안 2 | `DB_RESET_TOKEN` 으로 전체 초기화 | 상담·장애·판별기준 수정까지 모두 지워짐 |
| 안 3 | 시작할 때마다 고치는 SQL을 실행 | 나중에 `user02` 를 새로 만들면 다음 재시작에 또 이름이 바뀌고 비밀번호가 초기화됨 |
| 안 4 (고른 안) | 시작할 때 한 번만 실행하고 기록 | 기록용 `app_meta` 를 씀(이미 `DB_RESET_TOKEN` 이 쓰는 표) |

## 결정

- 안 4로 정했습니다. 여러 인스턴스가 동시에 시작해도 DB 잠금으로 한 곳만 적용합니다.
- 빈 DB에서는 `SQL_FILES` 에도 같은 파일이 들어 있어 시드와 함께 실행되고, 시작 때 한 번 더 실행돼도 바뀔 것이 없도록 SQL을 씁니다(예: `user` 가 이미 있으면 아무것도 하지 않음).
- 시드(05)는 `user` 로 바꾸되, 예전 `user02` 가 있는 DB에서는 `user` 를 새로 만들지 않습니다. 같은 사람의 계정이 둘 생기지 않게 하려는 것입니다.

## 결과

- 코드: `backend/app/db_init.py` 의 `apply_updates`, `backend/main.py` 시작 단계, `backend/sql/14_rename_it_account.sql`
- 앞으로 기존 DB에도 꼭 반영해야 하는 변경은 SQL 파일을 하나 만들고 `UPDATE_SQL_FILES` 에 추가합니다. 이미 적용된 파일은 고쳐도 다시 실행되지 않으므로, 고칠 일이 생기면 새 파일을 만듭니다.
