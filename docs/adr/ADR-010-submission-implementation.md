# ADR-010 제출 구현은 VocAi로 하고, 요건 문서와 잇는다

- 상태: 검토 중 (팀 확인 전)
- 날짜: 2026-10-30 (기록한 날입니다. 방향은 10/28 회의와 10/29 발표자료 작업에서 정해졌습니다)

## 요약

대회에 제출하는 구현은 이 저장소의 코드(VocAi: FastAPI + LangGraph + Vue 3)입니다.  
팀이 정한 요건과 개발 흐름 문서는 이 저장소의 `docs/`에 두고, 제출 구현이 요건 가운데 무엇을 하는지는 [vocai-status.md](../requirements/vocai-status.md)로 잇습니다.

## 배경

ADR-002의 흐름(요건과 설계를 사람이 먼저 정하고, AI는 그대로 구현하고 검증하는 일을 돕는다)을 따라 요건·아키텍처·디자인을 먼저 정했습니다.  
요건과 설계를 따라 시연용 구현(Next.js + React + PostgreSQL, 다른 저장소)을 따로 만들어 10/26에 배포했습니다. 그 구현을 써 보며 나온 피드백이 요건(탭 7개, 역할 넷, 텔레그램 고객 시연 등)에 반영됐습니다.  
같은 시기에 개발 담당이 VocAi를 만들고 있었습니다. 그래서 구현이 둘이었고, 사전 제출(10/30 24:00)에는 하나만 낼 수 있습니다.

## 검토한 안

| 안 | 내용 | 장단점 |
|---|---|---|
| 안 1 | 시연용 구현을 제출한다 | 요건 문서와 구현이 거의 같습니다. 하지만 10/27에 큰 틀과 기능의 기준을 VocAi로 정했고, 10/29부터 발표자료의 프로그램 설명도 VocAi 기준으로 씁니다. |
| 안 2 (고른 안) | VocAi를 제출하고, 요건·개발 흐름 문서는 이 저장소에 두어 VocAi와 잇는다 | 구현은 개발 담당이 이미 갖춘 것을 그대로 씁니다. 요건 문서와 구현이 다른 곳은 숨기지 않고 대응표에 남깁니다. |
| 안 3 | VocAi를 요건 문서에 맞게 새로 고쳐 만든다 | 문서와 구현이 가장 잘 맞습니다. 하지만 마감(10/30 24:00)까지 남은 시간이 짧습니다. |

## 결정

안 2로 정했습니다.

- 기록된 근거: 10/27에 요건과 VocAi를 맞댈 때 「큰 틀과 기능은 v2가 맞다」고 정했습니다(v2는 VocAi입니다)([scope.md](../requirements/scope.md) 질문지 24번). 그 뒤 10/28 회의에서 프로그램 보완은 개발 담당이 맡기로 했고, 10/29 발표자료는 VocAi 기준으로 다시 썼습니다.
- 요건 문서(`docs/requirements/`)는 팀이 정한 목표 기준선으로 둡니다. 제출 구현이 요건을 모두 채우는 것은 아니므로, 항목마다 구현 여부를 [vocai-status.md](../requirements/vocai-status.md)에 적습니다.
- 앱 코드는 저장소 맨 위의 `backend/`(FastAPI)와 `frontend/`(Vue 3)에 있습니다. 개발 흐름 문서와 에이전트는 `docs/`, `harness/`, `.claude/`에 둡니다([ADR-001](ADR-001-folder-structure.md)).
- 기술 스택은 구현된 것을 [ADR-007](ADR-007-tech-stack.md)에, 구조와 동작은 [architecture.md](../architecture/architecture.md)에 정리했습니다.

## 이 결정으로 달라지는 것

- 요건 문서의 「우리 것」「앱」「배포 뒤」는 시연용 구현을 가리킵니다. 문서 앞머리에 그렇게 적어 두었습니다.
- ADR-008(디자인 에이전트)의 화면 부품 기준(HeroUI)과 ADR-009(구현 계획 한 장)의 구현 단계는 시연용 구현에 적용한 것이라 이 저장소의 코드에는 해당하지 않습니다. 두 ADR의 앞머리에 적용 범위를 적었습니다.

## 아직 확인할 것

- 이 ADR의 상태는 팀이 읽고 확인한 뒤 「채택」으로 바꿉니다.
- 시연용 구현에만 있던 요건(탭 7개 구성, 역할 넷, 텔레그램 고객 시연 등)을 제출 구현에 얼마나 반영할지는 정하지 않았습니다.
