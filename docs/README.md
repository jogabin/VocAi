# 개발 문서

이 폴더는 콜록 홈즈의 요건·구조·결정 문서입니다.  
무엇을 만들기로 했는지(요건), 어떻게 생겼는지(아키텍처), 왜 그렇게 정했는지(결정 기록)를 한곳에 모았습니다.  
코드는 저장소 맨 위의 `backend/`와 `frontend/`에 있고, 실행 방법은 [루트 README](../README.md)에 있습니다.

## 읽는 순서

| 순서 | 알고 싶은 것 | 문서 |
|---|---|---|
| 1 | 시스템이 어떻게 생겼나 | [아키텍처](architecture/architecture.md) |
| 2 | 무엇을 만들기로 했나 | [범위](requirements/scope.md) → [요건정의서](requirements/requirements.md) → 탭별 요건 [tabs/](requirements/tabs/) |
| 3 | 요건 중 무엇이 구현됐나 | [요건 대비 구현 현황](requirements/vocai-status.md) |
| 4 | 왜 이렇게 정했나 | [결정 기록](adr/README.md) |
| 5 | 요건·설계 문서를 어떤 흐름과 도구로 만들었나 | [SDD 한눈에 보기](guide/sdd.md) |
| 6 | 배포하고 운영하는 법 | [배포와 운영](deploy/deploy.md) |

## 폴더

| 폴더 | 무엇이 있나 |
|---|---|
| `adr/` | 결정 기록. 무엇을 고민했고, 어떤 안을 비교했고, 왜 골랐는지 |
| `requirements/` | 범위(`scope.md`), 요건정의서(`requirements.md`), 탭별 요건(`tabs/`), 요건 대비 구현 현황(`vocai-status.md`) |
| `architecture/` | 아키텍처. 에이전트 흐름, 데이터, API, 권한, 설정값 |
| `deploy/` | 배포와 운영 |
| `guide/` | SDD(스펙 주도 개발) 흐름과 개발 에이전트 한눈에 보기 |

개발 단계는 인터뷰와 요건 → 아키텍처·디자인 → 스펙 → 구현 계획 → 구현 → 검증 → 배포입니다([ADR-002](adr/ADR-002-dev-flow-and-agents.md)).  
이 저장소에는 그중 요건·아키텍처·배포 문서가 있습니다. 디자인·스펙·구현 계획·검증 문서는 아직 없습니다([ADR-009](adr/ADR-009-build-without-spec-agents.md)).

## 문서 상태

문서 맨 위에 상태를 적습니다: 작성 중 → 확인 대기 → 확정.  
**확정은 사람이 읽고 확인했다고 말할 때만 합니다.** 지금 대부분의 문서는 확인 대기입니다. 쓴 뒤 사람이 읽고 확인한 것이 아니라는 뜻입니다.

| 문서 | 상태 |
|---|---|
| 범위, 요건정의서, 탭 1~6 요건 | 확인 대기 |
| 탭 7(성과측정) 요건 | 확정 |
| 요건 대비 구현 현황, 아키텍처, 배포와 운영 | 확인 대기. 구현된 코드를 읽고 정리한 것이며 앱을 실행해 확인한 것은 아닙니다 |
| ADR | 문서마다 다릅니다. 목록은 [adr/README.md](adr/README.md) |

## 읽을 때 알아 둘 것

- **요건 문서는 팀이 정한 목표 기준선입니다.** 제출 구현이 모두 채운 것은 아닙니다. 어디까지 구현됐는지는 [요건 대비 구현 현황](requirements/vocai-status.md)이 말해 줍니다. 문서와 코드가 다르면 코드가 맞습니다.
- 요건 문서의 「우리 것」「앱」「배포 뒤」는 제출 구현에 앞서 만든 시연용 구현을 가리킵니다([ADR-010](adr/ADR-010-submission-implementation.md)).
- 이 저장소의 앱 코드는 개발 담당이 따로 만들었고 요건·설계 문서대로 만든 것이 아닙니다. 아키텍처·배포 문서와 요건 대비 구현 현황은 완성된 코드를 읽고 나중에 정리한 것이며 개발 에이전트가 만든 것이 아닙니다.
- 개발 에이전트는 10개를 계획했고 4개(인터뷰, 요건정리, 아키텍처, 디자인)를 만들었습니다. 이 4개는 `.claude/skills/`에 있습니다. 나머지 6개는 만들지 않았습니다([ADR-009](adr/ADR-009-build-without-spec-agents.md)).
- 원본 자료(대회 공고, 팀 내부 문서, 참고 화면 등)는 공개 저장소에 두지 않습니다([지킬 것](../harness/ground-rules.md)).
